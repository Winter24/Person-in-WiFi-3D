# Ablation Results and Efficiency Analysis

This section reports the internal 20-epoch ablation study used to select the WiFi-based 3D pose model. The selected configuration is `M9_RF2`, which uses the trained `M9` checkpoint with two rectified-flow inference steps. Under the same evaluation protocol, this configuration achieves 165.487 mm MPJPE, improves over the original Person-in-WiFi 3D PETR baseline by 7.053 mm, and improves over the one-step `M9` inference by 2.599 mm. It also preserves the efficiency advantage of the compact Mamba2-CSI design, reaching 209.9 FPS with 3.618M parameters compared with 118.7 FPS and 13.130M parameters for the original baseline.

## Experimental Protocol

All models were evaluated with the same Person-in-WiFi 3D test protocol and the same primary metric, mean per-joint position error (MPJPE). Results are reported both as overall MPJPE and as occupancy-specific MPJPE for one-person, two-person, and three-person scenes. Runtime was measured with the project benchmark tool using CUDA inference and includes end-to-end latency, frames per second, parameter count, and peak allocated memory. The ablation follows a controlled path from the original PETR-style baseline to the selected design: `M0` is the original linear-input PETR baseline, `M1` isolates spectral tokenization while retaining PETRHead, `M7` introduces the WiTiDAR head under a Transformer encoder, and `M8` and `M9` compare Mamba-family encoders under the same WiTiDAR-flow formulation. The `M9_RF2` row evaluates the same trained `M9` checkpoint with a two-step rectified-flow solver, so the solver effect is separated from retraining effects.

## Main Ablation Study

The original PETR baseline (`M0`) achieved 172.540 mm MPJPE with 8.423 ms latency, 118.7 FPS, and 13.130M parameters. Replacing the linear WiFi input adapter with the spectral tokenizer while keeping the PETRHead (`M1`) improved MPJPE to 169.271 mm. This result shows that the spectral representation is beneficial for WiFi-based pose estimation, but the improvement came with a clear runtime cost: latency increased to 12.039 ms and throughput decreased to 83.1 FPS. The spectral tokenizer therefore improves representation quality, but it does not by itself provide the desired accuracy-efficiency trade-off.

Replacing PETRHead with the WiTiDAR head improved the balance between accuracy and cost. With the Transformer encoder, `M7` reached 168.342 mm MPJPE while reducing latency to 6.860 ms and parameter count to 7.059M. The Mamba-family variants then tested whether the encoder could be made smaller and faster under the same WiTiDAR head. The Mamba-1 variant (`M8`) achieved 169.653 mm MPJPE, while the flattened Mamba2-CSI variant (`M9`) achieved 168.086 mm MPJPE with only 4.833 ms latency and 3.618M parameters. This made `M9` substantially faster and smaller than the PETR baseline while already improving MPJPE by 4.454 mm.

The best accuracy was obtained by applying two rectified-flow inference steps to the trained `M9` checkpoint. This selected configuration (`M9_RF2`) reduced MPJPE to 165.487 mm. The gain was not isolated to a single occupancy regime: `M9_RF2` achieved 121.785 mm, 159.341 mm, and 190.179 mm MPJPE on one-person, two-person, and three-person scenes, respectively. Relative to the original PETR baseline, it reduced MPJPE by 4.09%, increased throughput from 118.7 FPS to 209.9 FPS, and reduced parameter count by 72.45%. These results establish `M9_RF2` as the strongest internal accuracy-efficiency point among the tested 20-epoch configurations.

## Flow Inference Analysis

The supplementary flow analysis clarifies why the selected configuration should use two-step rectified-flow inference rather than the originally logged one-step inference. Disabling flow on the `M9` checkpoint produced 167.732 mm MPJPE, while one-step rectified-flow inference produced 168.086 mm MPJPE. This indicates that the original one-step update did not reliably improve the final decoded pose. In contrast, two-step inference reduced MPJPE to 165.487 mm and reduced matched-only MPJPE to 163.886 mm, showing that the gain reflects better pose refinement rather than only a change in missed-person penalties.

The result does not imply that more solver steps are always better. In the retrained `T_FW2_20e` branch, two-step inference achieved 167.981 mm MPJPE, and four-step inference worsened MPJPE to 169.454 mm while also reducing throughput to 177.4 FPS. This branch therefore does not support replacing the selected `M9_RF2` model. The evidence instead supports a narrower conclusion: the original `M9` checkpoint benefits from correcting the rectified-flow inference solver to two steps, whereas retraining with lower flow loss weight or increasing the solver to four steps does not improve the selected result.

## Efficiency Analysis

The selected `M9_RF2` configuration preserves the efficiency advantage expected from the flattened Mamba2-CSI encoder. It uses 3.618M parameters and 25.29 MB peak allocated memory, compared with 13.130M parameters and 155.60 MB for the original PETR baseline. Its measured latency is 4.764 ms, corresponding to 209.9 FPS, which is faster than the PETR baseline and also slightly faster than the measured one-step `M9` benchmark. The section-level latency profile shows that most runtime is concentrated in the WiTiDAR encoder, while the compact backbone and decoder attention remain lightweight. This makes `M9_RF2` a practical candidate for reporting as the proposed model in the internal ablation narrative.

## Limitations

The current evidence is sufficient for the planned internal ablation section, but it should be interpreted as a single-checkpoint model-selection result. Variance from random initialization has not been quantified in this run set. The supplementary comparison also reveals a detection-refinement trade-off: the draft `M6` model has fewer missed persons than `M9_RF2`, but its overall MPJPE is 2.086 mm worse. This limitation should be reported transparently, especially if the paper later expands from an internal ablation study into a stronger journal or top-conference submission.
